## 4. 直播最终边界

取消上一轮50至70频道的上限和地方台/小众卫视/外语电视的默认删减建议。保留所有正常电视频道，含各地、市县、少儿、体育、电影、纪录和国际电视。

三个直接入口移出：虎牙一起看、斗鱼一起看、YY轮播。本机只读检查确认三个目录当前都可读取，分别有1116、948、556个EXTINF条目；它们是平台列表条目，不是确认的电视频道数，也没有完成内容或实际播放审核。

自有聚合列表中确认属于平台游戏、主播、影片轮播的条目也排除，防止从候选目录再次导入。CHC等真实电视电影频道、正常电视节目频道不能因为播放电影而被当成平台轮播删除。来源不明时先登记待确认，不能仅凭名字或播放内容猜测频道身份。

占位、推广、时间戳等先核查流的实际身份：若实际流对应真实频道，修正名称并保留；确非频道才从APP列表移出，保留原始审计记录。任何已确认的成人/污染线路继续隔离，不能因“全保留”而放行。

## 5. 本轮确认的直播错误

旧版live.m3u共有1024条记录、823个现有tvg-id、826种原始显示名，只有955个不同URL，即69条完全重复URL记录。以上仅为文件结构计数，不是当前播放验证或确认后的电视台数。

发现8个tvg-id存在名称或分组变化，包括CCTV16、4K/8K、上海第一财经、苏州4K、河北都市等。关键缺陷：

- norm_name先删4K/8K，实际将CCTV-4K HD (1080p)与CCTV-8K HD (1080p)合成同一个ID。必须拆回独立频道，不能只做去重。
- CCTV台号与括号清晰度的处理不统一，同一频道会有多个显示名；CCTV-5和5+须持续分开。
- CHC/NEWTV/DOX等前缀被宽泛删除，存在误合并不同服务的风险。
- 同一URL在不同别名或分组重复出现；不能因此自动删除另一个频道身份，须先判定别名或误标。
- 分组关键词造成上海第一财经进入央视、苏州4K进入卫视、节目名含“凤凰/国际”等进入港澳国际等问题。
- 同一频道同一host只测一次，会丢掉同主机不同路径或不同清晰度的有效备用。
- parser仅保留名称/分组/logo，没有完整继承真实tvg-id、User-Agent、Referer、Origin等播放参数。
- 1024条记录的EPG ID全部由规则拼成 *.fqzone.tv，没有在构建中校验它们与所用节目表ID对应。
- 探测主要判断HTTP响应及明显HTML，尚未覆盖HLS子列表、分片、密钥、限流、鉴权有效期和实际解码。

全部电视身份迁移表需要覆盖每条旧记录：保留、别名归并、4K/8K拆分、误标修正、平台轮播排除、非频道移出或待确认。纠错后的频道数可以变化，不能用“必须仍然823”代替覆盖验收。

## 6. 频道、线路与排序规则

频道channel_id长期稳定；名称、分组、logo、EPG单独管理。线路归属于频道，保存完整播放URL、必要headers、来源、清晰度、鉴权刷新方式和探活证据。完整原始线路保存在库中，APP通常展示2至3条优选备用。

普通重复线路归并；分辨率差异可以是同频道线路，但独立4K/8K服务、地区版、时移版、CCTV5+等按真实身份分开。签名query不能被粗暴清掉。逻辑线路身份与会变动的鉴权URL分开记录。

分组可保持老版风格并校正：央视、卫视、电影剧场、体育、少儿动漫、纪录科教、港澳台、国际、地方（按省份）、其他待确认。频道位置固定；频道内线路依据实际网络健康选择，避免每日测速导致频道跳动。

单次失败不删频道。优先切换备用并保留历史；无有效线路时记录暂不可用和替换缺口，不伪造可播放地址。频道身份保留不等于能够承诺外部广播服务永久供流。海外CI失败不能覆盖国内成功证据。

## 7. 原生插件是迁移的首要阻塞项

静态检查使用与远端Git blob完全一致的cfg.jpg。全部24个旧配置要求的csp类定义存在，但当前包未定义HideUtils或CryptoBridge。DexNative只有GoWeb原生声明，缺少修复脚本所列的8个原生桥方法；Init中也未见修复方案要求的context方法。

仓库有restore_native_crypto.py、verify_native_crypto.py和修复说明。文档记载的native oracle测试不能证明修复已进入当前发布包。必须针对真实候选插件执行修复与验证，并保留原有类、Guard映射、ARM32/ARM64资源和MD5一致性。

精简后仍有奶酪、光影、热播、茉莉、剧圈、咕咕6项不透明ext站。它们的解密与真实站点请求应单独验收，不继续按“无法探测所以永不降级”认定可用。静态缺桥是已确认事实；各站最终播放结果仍待Android运行验证。

部分原生适配器目前只有二进制，没有完整可重建源码。可以先自托管、固定版本并兼容验证；后续逐站提取接口和编写可维护适配器。未完成部分不能被宣传为已彻底获得全部源码维护能力。

## 8. 动态视频内容过滤

当前入选27个CMS在缓存中都是mixed。分类导航白名单不能过滤所有搜索/详情/播放结果，缓存还会因已有verdict被跳过刷新。仅移除18个周边入口不足以解决色情内容风险。

建议在自己的插件增加可维护的CMS过滤适配器，对上游列表、搜索、详情、播放四个路径统一检查分类/内容/提供方与媒体域名，并持久化污染隔离。仍可动态浏览大量正常作品，不做固定片目限制。分类缓存有有效期与复审证据，失败不能直接跳过安全策略。

这可能需要将原type=1直连接口改为自有type=3包装适配器，保留站点key、名称、分类和换源能力。纯静态npm JSON无法截获APP直接访问CMS时返回的所有结果；若坚持type=1完全不变，就需要自有CMS代理服务或APP修改。优先选插件包装，以避免新增长期运行的服务器。

原生站的Guard名称不能作为过滤充分的证据，也要验证实际返回路径。通过正常分类或标题不等于对每集内容做了完整认证，实际抽帧和污染举报处理仍须保留。

## 9. 自有维护与目录

在独立仓库恢复checker/output/scripts/workflows的清晰职责，新增明确的数据登记层；不整包复制旧仓库的过时脚本和暂存文件。

建议：checker负责站点/频道探测、过滤和构建；registry或同职责数据目录保存站点、频道、线路、依赖登记；policy保存策略；state保存按网络划分的健康和隔离；reports保存审核、探活、迁移和发行证据；output保存生成资源；scripts只保留构建/推送/发行命令；npmstage作为可清理的发行暂存，不再提交嵌套副本。

从旧配置一次性导入本地站点参数与全部电视线路，来源作者配置从必要构建依赖降为可选发现渠道。插件、远程JSON、脚本与logo等需要的静态文件纳入自己的发行闭包。CMS、广播流和节目表服务仍是外部服务；停止供流或接口改变时需要自己修适配器或补充线路。

## 10. 单一生产流水线

本地登记库 -> 内容/身份准入 -> 按网络探活和健康更新 -> 视频主候补选择/频道别名与分组修正 -> 构建实际插件和配置 -> 迁移覆盖及兼容检查 -> npm next候选 -> registry/CDN全资源验证 -> 双端APP验收 -> 按验收结果提升latest。

健康更新在最终排序和构建前完成，避免晚一轮生效。候选发现失败继续使用自己的已登记数据；发布或校验失败必须明确失败并保留上一可用发行，不能echo吞掉错误或发布空配置。一次候选发行按同一版本冻结API、插件、直播和其他依赖，不混用旧包@latest。

本机Python固定使用用户指定路径；GitHub Actions使用runner环境的Python。沿用api_push.py和GitHub Actions，NPM_TOKEN已在实际0.4.1发行中验证。推送须先核对远端HEAD，不force覆盖他人新提交。

周期建议：两小时轻检查、每日中国时间07:00全量检查、每周内容与身份复审；未审核的新候选不自动上线。自动更新可使用已批准备用线路，异常或大面积退化熔断。固定版本地址用于用户明确通知他人二次导入，通知仍由用户自己的渠道完成。

1. 冻结旧0.1.26基线和当前独立发行，导入61站及全部直播原始资料，产出每条记录迁移对照。
2. 视频移出18项、直播排除平台目录，电视频道全部登记；恢复多站插件、原生桥和配套参数，优先验证首页及6个密文站。
3. 接入动态CMS内容过滤与原生返回审核；首页/分类/搜索/详情/分集/换源均通过。
4. 修复直播名称、错误合并、分组、EPG和headers；逐频道探测、身份核验和备用切换，处理无有效线路缺口。
5. 合并为一条构建发布流水线，验证失败保护、可重建、固定版本CDN闭包以及回滚。
6. 发布候选，用户提供的手机/TV APK分别实测，再上线。两个APK均声明minSdkVersion=25，应以实际客户端兼容性为准。

硬验收：

- 配置中的csp类确实存在于发行DEX；native桥和ABI资源验证通过；编译stub不进入发行。
- APP动态首页及正常分类存在；跨站搜索、精确匹配、分集与换源可用。
- 成人分类、混合库搜索/详情与已隔离播放线路均有实际拦截证据。
- 每条旧直播记录有迁移去向，每个真实电视身份有保留/更正说明；不存在按地区或热度删除。
- CCTV5/5+、4K/8K和跨台同名不会误合并；同频道重复记录归并，有效备用及必要鉴权参数保留。
- HLS列表/子列表/密钥/媒体片段与代表频道真实解码验证；domestic与CI证据分开记录。
- 发布包、manifest、插件MD5、registry及CDN字节一致；回滚到上一已验证版本有可执行流程。
